# Agent Tool — プロダクト要件書

AI コーディングエージェントの Skill、Subagent、Rule、MCP サーバー、Plugin を管理する
Cursor 拡張と、Skill と Subagent の検知・導入を担うブラウザ拡張。

| 項目 | IDE 拡張 | ブラウザ拡張 |
|---|---|---|
| 識別子 | `agent-tool` | `browser/manifest.json` |
| 対象 | Cursor / VS Code | Chrome / Edge / Brave |
| 対象 OS | macOS / Linux / Windows | 同左 |
| 実装 | TypeScript | TypeScript |
| 永続メタデータ | `globalStorageUri/registry.json` | IndexedDB のディレクトリハンドル、収集一覧、自動表示設定 |

両者は独立して動作する。ブラウザ拡張は IDE 拡張の導入も起動も前提にしない。

## IDE 拡張の機能

- Dashboard でユーザー全体とワークスペースのツールを一覧表示する。
- 公開 GitHub URL から Skill、Subagent、Plugin を追加する。Rule は URL からの追加を提供せず、
  既に置かれているものの表示・削除だけを担う（D-20）。
- 構造化 JSON、HTTP URL、または安全なコマンドから MCP サーバーを追加する。
- 削除、更新プレビュー、更新適用を提供する。
- Dashboard は一覧から導いた読み取り専用の診断を表示する。診断は競合、壊れたリンク、
  `SKILL.md` の欠落、MCP の起動コマンド未解決を対象とする。
  「環境を診断」はこの診断結果を集約して表示するだけで、別の走査や永続ログを持たない。
- Plugin の設定変更は対象 CLI の実行コマンドを表示して確認を求める。
- ブラウザ拡張が残した取得元の台帳を走査時に `registry.json` へ取り込む。

## ブラウザ拡張の機能

- 初回オンボーディングで利用する Agent の導入先を一度だけ許可する。
- 対応サイトの閲覧中に、そのページが Skill / Subagent なら検知し、拡張の popup を開く。
- カタログ由来の候補は、GitHub アーカイブから実体を抽出できることを確認してから検知する。
- 貼り付けた URL を検知と同じ判定で解析する。
- 未対応サイトでは手動スキャンと、利用者がサイト単位で許可した自動検知を提供する。
  ローカル判定を優先し、決められないときだけ有効化済みの Jev 補助（**Beta**、既定は無効）を使う。
  ページ全文は送らず、抽出した GitHub リンク、導入コマンド断片、見出し等だけを送る。
  AI 判定だけでは導入せず、既存の GitHub 実在確認・展開確認を必ず通す。
- 導入先のエージェントを選び、File System Access API で実体を書き込む。
- 自分が入れたものを削除する。
- 導入したものをブラウザ内の収集一覧に保持する。
- `Supported sites` から GitHub と対応カタログを開ける。

MCP と Plugin は扱わない。ローカルの導入済み一覧も表示しない。スコープはユーザー全体だけとする。

### 未対応サイトの検知改善

手動スキャンと、利用者がサイト単位で許可した自動検知は同じ判定処理を通る。
H1〜H4 は下記の内容で実装済みとし、以降の変更もこの 4 点を退行させない。

| ID | 満たすこと |
|---|---|
| H1 | 複数候補は件数だけに潰さず、popup に一覧で出す。名前・種別・取得元を見て 1 件を選び、実在確認に成功したものだけ既存の導入画面へ進める |
| H2 | キー未登録・Jev 無効でもローカル検知と H1 を利用できる。Jev が必要になったときだけ設定を案内する |
| H3 | コードブロックは行単位で読み、repo と `--skill` の指定名を対応付ける。規約どおりの置き場を HEAD 1 回で確かめ、複数 repo を先頭 1 件へ縮めない |
| H4 | 古いページの非同期結果を反映しない。遅延描画を上限付きで再走査し、権限解除・タブ終了時に処理を無効化する |

- UI と操作は [UI 設計 §10.3.2](agent-tool-ui-design.md#1032-未対応サイトの検知改善)、
  判定・上限・信頼境界は [セキュリティ §10.5.1](agent-tool-security.md#1051-未対応サイトの検知改善)、
  検証は [テスト計画](agent-tool-test-plan.md#未対応サイトの検知改善)を正本とする。
- 抽出先ホストの追加、本文位置による優先順位付け、任意配置の探索、Jev の再訪結果キャッシュ、
  `#fragment` 変更イベントの追加、規約外に置かれた Skill の実在確認は含めない。
  これらは必要になった時点で、範囲を別途決める。
- 新しい依存ライブラリ、AI サービス、閲覧履歴や診断ログの永続保存は追加しない。

## 安全性

- IDE 拡張の書き込みは `writeGuard.ts`、`registry.ts`、`mcpScanner.ts` に限定する。
- 未信頼ワークスペースと Remote 環境では書き込みを拒否する。
- 走査対象は `source.ts` のホワイトリストに限定する。
- ブラウザ拡張は利用者が許可したディレクトリの外へ書き込まない。
- 未対応サイトの手動読み取りは `activeTab + scripting` を使う。自動検知は利用者が明示的に許可した
  HTTPS origin だけを対象にし、`<all_urls>` を要求しない。Jev API key は `chrome.storage.local` を
  trusted extension contexts に制限して保存する。
- 可変メタデータ以外のキャッシュ、ログ、Undo スナップショットを保存しない。
- MCP の健全性確認のために、利用者が設定したコマンドを起動しない。起動状態は View 表示中の
  既存プロセス照合だけで確認する。

## 確定した拡張方針

- [x] 更新は、同じ解決済み SHA から作った既存の Diff Editor を正本とする。表示には
  追加・削除・変更ファイル数、manifest/configuration の変更、本文を省略したファイルだけを要約する。
- [x] 競合は自動解決せず、実体の場所と比較導線を表示する。エージェント別の優先順位を公式仕様と
  テストで確認するまで、「実際に有効なコピー」は表示しない。
- [x] 互換性は `対応形式`、`導入済み`、`CLI 検出済み` を別の状態として扱う。
- [x] 複製・移行は互換性が確認済みの管理下かつ有効な Skill を、user と current project の間で
  copy する。宛先と上書きなしを事前表示し、管理外を含む既存の宛先は上書きしない。元は残し、
  link/move・形式変換・影響 Agent の推測は行わない。
- [x] 信頼度を数値化しない。可変 ref、アーカイブ済みリポジトリ、取得元の古さ、実行物・MCP・hook、
  環境変数、binary/archive を根拠付きの「要確認シグナル」として表示する。
- [x] 依存関係は宣言済みの Skill/MCP 参照と管理リンクだけから削除影響を表示する。本文の推測や
  グラフ表示は行わない。
- [x] Profile、ワークスペース推薦、ローカル使用分析は実装しない。Profile は desired state の保存先、
  推薦は信頼できるカタログ、使用分析は許容される信頼できる利用シグナルが決まった場合だけ再検討する。

## リリース条件

- `npm run typecheck`、`npm test`、不変条件検査、リリース検査が通る。
- Linux、macOS、Windows で型検査とテストが通る。
- Cursor Stable の E2E と VSIX の 20 MB 上限を確認する。
- ブラウザ拡張は Chrome / Edge / Brave で検知から導入までを実機確認する。
